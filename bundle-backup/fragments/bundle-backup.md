## Workspace Backup (bundle-backup)

This workspace is backed up as a `git bundle` after every commit, merge or rewrite, into the folder set with `git config bundle-backup.dest <folder>`: `<name>.bundle` is the latest state (every branch, full history) and `daily/<name>-YYYY-MM-DD.bundle` keeps the last state of each day. It covers committed work only — uncommitted changes, git-ignored files and `.git/config` are not in it. The destination folder must exist (it is never created, so an unmounted sync folder fails loudly). A SessionStart check repairs a failed, interrupted, stale or damaged backup on its own, and says something only when the user has to act (no destination, the sync folder not mounted, a repair that failed); act on such a message rather than ignore it. Every backup step and repair is logged in `.git/bundle-backup.log` for investigating problems.

**Restore:** `git clone --mirror <folder>/<name>.bundle <repo>.git`, then `git clone <repo>.git <workspace>` — a plain `git clone` of the bundle checks out only its HEAD branch. The mirror clone checks every object and fails on a damaged bundle; `git -C <repo>.git fsck --full` checks the result again. `git bundle verify` reads only the bundle's header, so it is not a check of its content.
