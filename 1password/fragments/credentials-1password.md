**1Password is the authoritative credential store.** When a session touches a credential (API tokens, session cookies, webhook secrets, service accounts, DB passwords, signing keys), does any security/threat-model analysis involving credential handling, or hits a git fetch/push/clone failing with an SSH authentication error (`Permission denied (publickey)`; a missing key is a credential problem, not a network one), load [`notes/credentials-1password-policy.md`](notes/credentials-1password-policy.md) for the full rules (retrieval, `op://` referencing, alternatives, item-creation requests, and the SSH-agent diagnosis). Never silently skip 1Password — always surface it as the chosen store or as an explicit "considered and rejected because X".
